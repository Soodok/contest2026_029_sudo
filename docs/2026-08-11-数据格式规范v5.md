# 《资料库》数据格式规范 v5

> 版本：v5.0（替代旧 v4 固定结构 / New PL 未定型逻辑）
> 目标：一套文件格式 + 字段配置，承载任意结构的数据库（历史/词典/单位/百科……含可选图片）
> 适用：引擎端 SearchEngine.js 适配、数据生成工具（New PL）、读取端（detail/result/index 页）适配
> 作者：队伍 029「sudo」 · 日期：2026-08-11

---

## 一、设计原则（为什么这样设计）

1. **固定文件结构与段序，字段含义由 meta 声明**——引擎按位置解析（简单可靠），知识库差异只在 meta。
2. **字段角色可配置**——每条记录的字段可扮演不同角色（搜索/显示/筛选/详情/图片）。
3. **图片可选**——有图就配，没图留空，不影响解析。
4. **兼容已有资产**——Block 哈希桶、LRU 缓存、年份索引沿用已验证逻辑。

---

## 二、字段角色体系（自定义的核心）

| 角色 | 说明 | 存储 | 参与搜索 | 数量限制 |
|---|---|---|---|---|
| `keyword` 关键词 | 搜索词；多词用 `,` 或 `，` 分隔，拆开后分别索引 | Block + Detail 关键词段 | ✅ | 任意 |
| `hiddenKeyword` 隐形关键词 | 只索引不显示（拼音/别名/英文名） | 仅 Block | ✅ | 任意 |
| `map` 简约 | 搜索卡片显示（标题/摘要等） | 仅 Map | ❌ | **≤3** |
| `filter` 筛选 | 分类/地区等筛选条件 | Detail 筛选段 + meta 声明值域 | ❌ | 任意 |
| `detail` 详情 | 详情页内容（释义/例句/原因/影响…） | Detail 详情段 | ❌ | 任意 |
| `image` 图片 | 卡片或详情配图（存路径，图片文件随包） | Map 或 Detail 存路径 | ❌ | 任意 |

**角色可组合**：同一字段可同时是 `keyword`+`map`（如"标题"既可搜又显示）或 `detail`+`image`。
**互斥规则**：`keyword` 与 `hiddenKeyword` 互斥；`map` 最多 3 个。
**简化规则**：`map` 角色字段**不写 Detail**（简约只进 Map），除非同时是 `keyword`（此时关键词段要写）。

## 三、文件清单

```
<知识库目录>/（如 src/common/词典/）
├── meta.json              # 数据集信息 + 字段配置 + 分块信息（必填）
├── map_0.txt, map_1.txt…  # 简约卡片数据（按 mapChunkSize 分片）
├── detail_0.txt, …        # 详情数据（按 detailChunkSize 分片）
├── block_0.bin, …         # 哈希桶索引（二进制，可回退 .txt）
├── year_index.txt         # 年份→ID 索引（可选，year.enable=true 时）
└── images/                # 图片资源（可选，随 rpk 打包）
```

## 四、meta.json 完整定义

```json
{
  "formatVersion": 5,

  "dataset": {
    "name": "历史库",
    "version": "1.0.0",
    "author": "Soodok",
    "description": "中国与世界历史大事记",
    "icon": "/common/logo.png"
  },

  "totalCount": 2533,
  "bucketSize": 4096,

  "fields": {
    "map": [
      { "name": "标题", "weight": "high" },
      { "name": "摘要", "weight": "medium" }
    ],
    "filter": [
      { "name": "分类", "values": ["古代", "近代", "现代", "世界"] }
    ],
    "detail": [
      { "name": "原因/背景" },
      { "name": "影响" }
    ],
    "keyword": [ { "name": "关键词" } ],
    "hiddenKeyword": [],
    "image": [ { "name": "配图" } ]
  },

  "year": {
    "enable": false,
    "rules": [ { "min": 1, "max": 500, "display": "唐代" } ],
    "defaultDisplay": "公元{value}年"
  },

  "chunks": [
    { "id": 0, "bucketStart": 0, "bucketEnd": 649, "recordCount": 4009 }
  ],
  "mapChunkSize": 100,
  "detailChunkSize": 100,
  "maps": [
    { "id": 0, "startId": 0, "endId": 99, "recordCount": 100 }
  ]
}
```

**字段说明**：
- `fields.map`：数组，第 i 项对应 map 文件第 i 个简约列；`weight` 用于排序权重（high/medium/low）
- `fields.filter`：声明筛选字段及值域（引擎/页面据此生成筛选标签）
- `fields.detail`：详情段各列标签（详情页按此渲染标题）
- `fields.keyword` / `fields.hiddenKeyword`：搜索字段（引擎据此收集索引词）
- `fields.image`：图片字段（Map 存卡片图、Detail 存详情图，路径均指向 `images/` 下）
- `year.rules`：年份显示规则（范围→文本，`{value}` 占位）

## 五、文件格式规范

### 5.1 map_*.txt（每行一条，`|` 分隔，固定列序）

```
ID | [年份] | 简约1 | 简约2 | 简约3 | [卡片图路径]
```

| 列 | 说明 |
|---|---|
| ID | 记录号（0 起，与 Block/Detail 一致） |
| 年份 | `year.enable=true` 时存在；否则无此列 |
| 简约1..3 | 对应 `fields.map` 各列；不足的列留空 |
| 卡片图路径 | `fields.image` 配置且该库有卡片图时存在；可选 |

**示例**（year 开 + map 两列 + 无图）：
```
12|221|秦始皇统一六国|秦王嬴政灭六国建立秦朝
```

### 5.2 detail_*.txt（每行一条，`|` 分隔，固定段序）

```
ID | [年份] | 关键词串 | 筛选1|筛选2 | 详情1|详情2 | [详情图路径]
```

| 段 | 说明 |
|---|---|
| ID | 记录号 |
| 年份 | `year.enable=true` 时存在 |
| 关键词串 | 关键词字段值（`fields.keyword`），多词用 `,` 连接；`hiddenKeyword` 不入此段 |
| 筛选段 | `fields.filter` 各列值，段内用 `\|` 分隔；无筛选字段则该段省略 |
| 详情段 | `fields.detail` 各列值，段内用 `\|` 分隔；无详情字段则该段省略 |
| 详情图路径 | 可选 |

**段序固定，空段省略会破坏位置** → **约定：各段始终按顺序出现，空段用空字符串占位**。示例（keyword+filter+detail+图）：

```
ID|年份|关键词串|筛选值1|筛选值2|详情值1|详情值2|图片路径
12|221|秦始皇,统一六国|古代|中国|战国末期战争|建立中央集权|images/hist/12.png
```

> ⚠️ **固定段序约定（关键）**：引擎按 meta 声明的列数解析：
> `[0]ID [1]年份(可选) [2]关键词串 [3..3+filter数)筛选段 [3+filter数..)详情段 [末尾]图片路径(可选)`
> 空值必须保留占位（`||`），不允许"跳段省略"。

### 5.3 block_*.bin（二进制，沿用 v3.4 格式）

- 头部：`BLOK(4B)|version(4B)|chunkId(4B)|bucketCount(2B)` + 桶条目 `bucketIndex(2B)|idCount(2B)|ids(idCount×4B)`
- 索引词 = 关键词字段 + 隐形关键词字段，**每个词整词哈希 + 每字符哈希**（`hashCode`，djb2 变体），取模 `bucketSize`
- 无二进制时回退文本：`bucketIndex|id1,id2,...`

### 5.4 year_index.txt（可选）

```
年份|id1,id2,id3
```

### 5.5 images/ 目录

- 图片路径存于 Map/Detail 的图片列，值为相对 `common/` 的路径，如 `images/hist/12.png`
- 页面渲染：`<image src="/common/images/hist/12.png">`（快应用路径以 `/common/` 开头）

## 六、完整数据流示例（一条历史记录）

**原始数据行**（`|` 分隔，8 列）：
```
秦始皇统一六国|221|统一六国,秦始皇,嬴政|古代|中国|战国末期连续征战|建立中央集权帝国|images/hist/12.png
```

**字段配置**（meta.fields）：
| 列 | 角色 |
|---|---|
| 列0 秦始皇统一六国 | keyword + map(标题) |
| 列1 221 | map(年份→year) |
| 列2 统一六国,秦始皇,嬴政 | keyword(多词) |
| 列3 古代 | filter(分类) |
| 列4 中国 | filter(地区) |
| 列5 战国末期连续征战 | detail(原因) |
| 列6 建立中央集权帝国 | detail(影响) |
| 列7 images/hist/12.png | image(配图) |

**生成文件**：
- `map_0.txt`：`12|221|秦始皇统一六国| |images/hist/12.png`
- `detail_0.txt`：`12|221|统一六国,秦始皇,嬴政|古代|中国|战国末期连续征战|建立中央集权帝国|images/hist/12.png`
- `block_*.bin`：索引"秦始皇统一六国""统一六国""秦始皇""嬴政"及每字哈希 → 桶 → ID12
- `meta.json`：按第四节模板

**页面表现**：
- 搜索"秦"→ 命中 ID12 → 卡片显示"221 秦始皇统一六国"（+ 缩略图）
- 进详情 → 年份/分类/原因/影响 分段渲染 + 详情图

## 七、引擎适配清单（SearchEngine.js）

| 位置 | 现状（v3.4） | 改为（v5） |
|---|---|---|
| `_loadMeta` | 读 v4 meta（regionList/categoryList） | 读 v5 `fields`（map/filter/detail/keyword/hiddenKeyword/image）+ `dataset` + `formatVersion`；保留旧 v4 兼容或直接切换 v5 |
| `_loadMapFromFile` | 硬编码 4 列 ID/年份/地区/标题 | **列数由 meta 动态定**：`ID|[年份]|简约1..N|[图]`；存通用 `displayVals` 数组 |
| Detail 解析（getDoc） | 固定列取原因/影响 | **按 meta 段序解析**：关键词串/筛选段/详情段/图片路径 → 返回 `{keywords, filters[], details[], image}` |
| `search` 展示 | 用 regionMap 映射地区名 | 卡片数据直接来自 Map 简约列（`mapFields` 名作标签可选） |
| 年份显示 | `_formatYearDisplay` 固定规则 | 按 `meta.year.rules` 动态映射（含 `defaultDisplay`） |
| 筛选 | 固定 region/category | 从 `meta.fields.filter` 动态生成筛选项 |

**目标**：引擎对"数据结构"零假设，只依赖 `meta.fields` 配置。

## 八、读取端适配清单

| 文件 | 现状 | 改为 |
|---|---|---|
| `detail.ux` | 硬编码"关键词/原因/影响"区块 | 按 `meta.fields.detail` 动态渲染（name=标签，value=内容）；筛选段显示为标签；图片列渲染 `<image>` |
| `result.ux` | 硬编码年份/地区/标题 | 简约列动态显示（取前 2 列作标题/摘要）；筛选按 meta 生成 |
| `index.ux` | 硬编码 categories/regions 数组 | 从 `meta.fields.filter` 生成筛选标签（各库不同） |
| `settings.ux` | 固定 | 知识库切换列表从可用库 meta.dataset.name 生成 |

## 九、数据生成工具（New PL）输出对齐要求

New PL v2.5 生成的 meta/map/detail/block 必须与本文第五、六节一致：
1. **meta 输出 v5 结构**（含 dataset、fields、year、chunks/maps）
2. **Map 固定列**：`ID|[年份]|简约1..3|[图]`（不要动态省略）
3. **Detail 固定段序**：`ID|[年份]|关键词串|筛选段|详情段|[图]`，**空值保留占位**
4. **图片列**：Map/Detail 可选最后一列，值 = `images/<库名>/<file>`
5. 移除/简化"每字段独立判断"UI：改为**每列勾选角色 + 输入列名**（模板式配置，更易懂）

## 十、各知识库字段配置模板（换 meta 即换库）

| 库 | map(简约) | filter(筛选) | detail(详情) | keyword | image |
|---|---|---|---|---|---|
| **历史库** | 标题、摘要 | 分类、地区 | 原因、影响 | 标题、关键词 | 配图 |
| **词典库** | 词、词性 | 语言 | 释义、例句 | 词 | 无 |
| **单位库** | 单位、类型 | 类别 | 换算关系、说明 | 单位、全称 | 无 |
| **百科库** | 词条、一句话 | 领域 | 定义、详述 | 词条、别名 | 配图 |

## 十一、实施顺序（依赖关系）

```
① 本规范定稿（本文档）   ← 正在做
② New PL 按规范输出 v5 数据   ← 工具适配
③ SearchEngine.js 适配 v5（meta/Map/Detail/筛选/年份）   ← 引擎适配
④ 读取端适配（detail/result/index/settings 动态渲染）
⑤ 用 4 个库数据验证全链路
```
> 顺序不可颠倒：格式是地基，引擎/页面都依赖它。
